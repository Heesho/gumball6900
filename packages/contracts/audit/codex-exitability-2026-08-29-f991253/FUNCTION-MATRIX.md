# Complete state-changing function matrix

## Method and coverage

This matrix was built from the current Solidity source and checked against the compiled ABI for each deployable
contract. It includes every locally declared and inherited `public` or `external` nonpayable/payable function. Compiler-
generated state getters and explicit view functions are not state-changing and therefore are described only when a
state transition depends on them. Constructors are included separately because immutable misbinding is a liveness
boundary. `SignalPortfolioLens` has no constructor logic, storage, custody, or state-changing ABI entry.

The current working source includes the CEX-01 lifetime-cap remediation in `Resonance.notifyRevenue` and ADR 0053's
CEX-02 Bribe claim authorization plus Resonance batch; original `f9912533` behavior is called out in those rows.

## SignalPortfolioLens

`packages/contracts/src/periphery/SignalPortfolioLens.sol` has **no state-changing function**. `portfolio` is an
unbounded caller-selected view loop over Strategies and, for each registered Strategy, the paired Bribe's bounded
maximum of sixteen tokens. It validates only that the supplied Resonance equals `SignalGBX.resonance()`. It has no
registry and does not prove Strategy provenance. RPC callers must chunk large lists. No onchain entry or exit calls the
Lens, so Lens, SDK, subgraph, event history, and frontend availability are discovery concerns rather than consensus
dependencies. None supplies a state-growth-independent bounded reconstruction for an unknown position key. An
offchain caller can derive factory CREATE candidates from the current factory nonce and query canonical mappings, but
that fallback grows with the complete number of graph contracts ever created (CEX-03).
